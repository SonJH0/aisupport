# 채용공고 데이터 관리

jobs.json에는 가상 예시와 검색 결과로 수동 정리한 실제 공고 후보가 섞여 있다. 검색 결과는 실시간 정보가 아니므로 원문과 현재 채용 상태를 확인해야 한다. 자동 수집은 구현하지 않았다. 개인 이력서와 개인정보, API 키를 저장소에 넣지 않는다.

## 데이터 필드

| 필드 | 내용 |
|---|---|
| id | 중복 없는 식별자 |
| company / title | 회사명과 직무명 |
| requirements | 공고에 명시된 자격 요건 |
| location | 근무 지역. 대한민국 전국을 대상으로 각 공고의 실제 지역 기재 |
| source | 출처 이름. 가상 공고는 반드시 가상 예시로 표시 |
| source_url | 실제 원문 주소. 가상 공고에는 넣지 않음 |
| checked_at | 공고 원문을 확인한 날짜, YYYY-MM-DD |
| deadline | 마감일, YYYY-MM-DD. 확인하지 못하면 빈 문자열 |
| description / skills | 공고에 실제로 명시된 업무와 기술 |

실제 공고는 공개된 검색 결과를 바탕으로 간단한 사실만 요약하고 출처 URL과 검색 결과 확인일을 기록한다. 원문이 직접 열리지 않은 경우 verification_note에 명확히 표시한다. 지속적 수집과 재이용 전 해당 사이트 조건을 확인한다. 마감일이 지난 공고와 잘못된 형식의 마감일은 검색에서 제외한다. 마감일 미확인은 검색 결과에 표시하고 AI가 사용자에게 확인을 안내한다. 날짜만으로 실제 채용 진행 상태를 보장할 수 없다. 현시점에 실제 공고의 자동 동기화·최신성 검증·중복 제거는 구현되지 않았다.

## 고용24 연동 검토

고용24 채용정보 Open API는 기업회원의 신청 및 승인된 인증키가 필요하다. 사용 조건과 세부 명세, 표시 의무를 검토하고 승인받은 후 연결한다. 인증키는 .env에만 보관한다. 현재 프로젝트에는 고용24 연동이 구현되어 있지 않다.

## RAG 학습 자료

knowledge.json에는 공식 학습 문서의 팀 요약과 원문 URL을 둡니다. 채용 필수 기준으로 해석하지 않습니다. ai/retrieval.py가 요청마다 문단 본문을 TF-IDF로 검색합니다. 가상 공고는 일반 RAG 검색 근거에서 제외되며 ID 직접 조회 시에도 가상임을 표시해야 합니다. 의미 임베딩이나 실시간 수집은 아닙니다.
