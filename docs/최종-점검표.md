## 2. 요구 범위 확인

원래 기능 명세의 ‘직무 추천’이 직무 목록 추천인지 채용공고 후보 추천인지 팀이 원문을 확인한다. 현재 구현은 공고 후보 검색이다. 문서에서 명칭만 바꿔 과거 미충족을 해결한 것으로 간주하지 않는다.

- 원래 명세의 문구·링크: 미확인
- 팀이 확인한 최종 요구 범위와 근거: 미확인
- 구현 보완 필요 여부: 미확인

## 3. 최종 배포본 Must 확인

서비스: https://ai-job-assistant-xewt.onrender.com

배포된 코드 커밋과 실행 시각을 먼저 기록한다. 새 대화에서 회차별로 시험하고 응답 원문 또는 화면을 연결한다. 기능별 3회 중 2회 이상 기대 결과가 나온 경우 그 시험 범위에서 충족으로 표시한다. 기존 자동 검사 74개와 bb1885e 보완의 97개 검사 기록을 이 횟수로 대체하지 않는다. 기존 증거를 사용하는 경우 실제 배포 버전과 전체 기대 결과가 일치하는지 먼저 확인한다.

## 4. 사용자 피드백의 남은 사실 확인

- [ ] 실제로 전달한 피드백 수집 질문·이용 안내 원문을 기록한다. 새 문구를 과거 질문처럼 넣지 않는다.
- [ ] T1~T5가 개발 직무 취업 준비 등 서비스 타깃에 해당하는지 실제 사실을 확인해 표에 추가한다. 타깃이 아닌 경우 해당 타깃 사용자에게 추가 테스트를 받는다.
- [ ] 연결된 의견 이미지에서 이름·연락처·닉네임·프로필 등 식별정보를 확인하고 남은 표시는 가린 사본으로 교체한다.
- [x] 다섯 의견이 긍정적이며 별도 수정 요청이 없어 기능 유지한 이유를 기록했다. 사용자 의견 때문에 새 기능을 수정했다고 주장하지 않는다.

## 5. 보안·접속·최종 제출

- [ ] 저장소 이력·공개 문서·첨부 이미지에 비밀값과 개인정보가 없는지 점검한다.
