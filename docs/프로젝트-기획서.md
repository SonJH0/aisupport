# AI 취업 비서 프로젝트 기획서

문서 기준일: 2026-10-28. 현재 구현과 관찰된 테스트를 정리한 문서이며, 아직 수집하지 않은 사용자 의견을 문제 검증 결과로 기재하지 않는다.

## 문제 정의와 대상

개발 직무를 준비하는 구직·이직 준비자는 학습 자료 탐색, 공고 조건 파악, 자신의 프로젝트 경험과 요건 비교에 시간을 쓴다. 일반적인 AI 답변에는 출처가 없거나 미기재 경험을 미보유로 판단하는 위험이 있다. 본 서비스는 출처 있는 학습 안내와 근거를 인용한 요건 비교를 제공한다. 이 문제의 빈도와 해결 가치에 대한 실제 사용자 인터뷰는 아직 확인되지 않아, 사용자 테스트에서 검증할 가설이다.

대상은 백엔드·프론트엔드 등 개발 직무를 준비하며 자신의 경험과 채용공고를 비교하려는 사람이다. 수업 교육생이라는 이유만으로 대상자로 인정하지 않고 실제 취업 준비 상황·사용 목적을 익명으로 기록한다. 다른 팀 교육생도 이 조건에 해당할 때만 포함하고 본 프로젝트 팀원은 5명에서 제외한다.

## 서비스 범위와 가치 가설

- 상담 질문에 관련 문서를 찾아 학습 방향과 출처를 안내한다.
- 직무·기술·신입 조건으로 인터넷 공고 후보를 찾고 미확인 조건을 구분한다.
- 사용자가 붙여넣은 공고와 경험을 요건별로 비교하고 확인 질문을 제안한다.
- 공고 이미지를 직접 읽고 제공되지 않은 정보는 추측하지 않는다.

기대 가치는 정보 탐색과 경험 정리의 부담 감소다. 실제 시간 절감·취업 성과·만족도 향상은 측정 전이므로 성과로 주장하지 않는다. 현재 모집 여부 확인, 원문 자동 크롤링, 합격 확률 예측, 경력 진위 검증, 장기 개인화 저장은 범위에 없다.

## AI와 기술적 접근

텍스트 상담은 LLM의 도구 선택과 실행 결과 활용을 사용한다. RAG는 외부 공식 문서의 팀 요약과 저장 공고 후보를 로컬 문단으로 보관하고 매 질문 TF-IDF 본문 검색 후 LLM 입력에 넣는다. 출처·문단 ID를 반환한다. 작은 자료집의 비용·구현 복잡도를 줄이기 위해 로컬 검색을 선택했으며 의미 검색·동의어·규모 확장에는 한계가 있다.

이미지는 Claude 호환 API에 직접 전송한다. Python/FastAPI는 AI 코드와 API·입력 검증의 통합에, HTML/CSS/JavaScript는 단순한 업로드·대화 UI에 사용한다. Render에서 정적 화면과 API를 같이 제공해 별도 프론트 배포 설정을 줄였다. GitHub와 Actions는 변경·자동 검사 기록을 남긴다. 필수 기술 근거는 Agent와 RAG이며 멀티모달도 실제 시험한 범위를 구분하여 기재한다. 기술별 코드와 아키텍처는 요구사항 정의서를 참조한다.

## 팀 구성

손재형: AI/Data, 손재윤: 백엔드, 황준식: 프론트엔드. 기존 문서의 분담을 유지한다. 실제 협업·의사결정·본인 기여는 각자가 작성하는 팀원별 기여 문서와 커밋에 연결한다. AI 보조가 생성한 코드·설명·기술 테스트와 본인이 검토·수정한 범위를 구분한다.

## 성공 판단과 위험

각 Must 기능은 명세의 확인 방법으로 3회 시도하고 2회 이상 기대 결과를 확인한다. 타깃 사용자 5명 이상에게 실제 서비스를 제공하고 의견 원문과 반영 내역을 익명으로 보존한다. 기술 테스트 성공을 실사용자 평가로 대체하지 않는다.

검색 요약의 최신성·누락, 이미지 판독 오류, AI의 근거 없는 조언, API 사용량·지연, 개인정보 전송 위험이 있다. 화면 고지·동의와 서버 검사, 미확인 상태 구분, 원문 확인 안내, 개인정보 없는 테스트를 사용한다. 이미지 출처 관련성과 화면 가독성은 남은 개선점이다. 과거 '직무 추천' 요구와 현재 공고 검색의 범위 차이는 원본 명세와 재대조해야 한다.
