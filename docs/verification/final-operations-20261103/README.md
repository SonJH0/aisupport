# 운영·보안 최종 점검 — 준비 및 확인 범위

작성 2026-11-03. 저장소 확인 기준 1dc7f5d. 이번 단계는 소스·이력의 제한된 후보 검사와 배포 점검 도구 준비다. 실제 배포 점검 및 계정 소유자 확인이 끝났다고 표시하지 않는다.

## 확인한 소스

- backend/main.py의 consent 기본값은 false이며 미동의 요청은 AI 함수 호출 전에 HTTP 403으로 거절한다. 동의 후에만 텍스트·이미지 경로로 전달한다.
- frontend/index.html에 입력 전 AI 생성 고지·외부 전송 설명·required 동의 체크가 있다. 정적 HTML 존재 확인은 브라우저 실제 조작 확인과 다르다.
- /health는 RENDER_GIT_COMMIT을 revision으로 반환한다. health 성공만으로 실제 AI 인증·모델 동작이 확인되는 것은 아니다.
- 서버 로그 코드는 요청 ID·상태·시간·revision 및 오류 종류·프레임을 기록한다. 사용자 입력·인증 값·예외 본문을 기록하지 않는 코드 구조를 확인했다. 실제 공급자·플랫폼 로그 전체를 감사한 것은 아니다.
- .env 및 변형 파일은 .gitignore 대상으로, .env.example만 예외다. Git ignore는 이미 노출된 이력을 삭제하거나 키를 폐기하지 않는다.

## 현재·이력 비밀값 후보 검사

[검사 원본](secret-scan.json): HEAD에서 도달 가능한 텍스트 blob 334개 검사, 바이너리 또는 2MB 초과 93개 제외. provider_key_shape, private_key_header, literal_secret_assignment의 제한된 패턴에서 이력·현재 파일 후보 0건, 추적 중인 실제 .env 파일 0건. 탐지값이나 키 부분 값은 저장하지 않았다.

재현 도구: `py -3 tools/check-secret-candidates.py`. 실행 시 새 날짜 파일을 남기며 후보 위치·패턴·건수만 기록한다. 대조한 Git object ID는 파일 객체 식별자이며 비밀값의 해시가 아니다. 실제 키 문자열을 출력하지 않는다.

이 결과는 무노출 인증서가 아니다. 삭제된/미수집 브랜치, 원격 첨부, 이미지 OCR, PDF·PPT 내부, 바이너리, 인식하지 못하는 키 형식·개인정보는 점검하지 않았다. ‘과거 노출 키 폐기 확인’과 ‘현재 키 동작’은 이 정규식 검사로 판단할 수 없다. 저장소 이력 전체를 다시 쓰거나 삭제하지 않았다.

## 실제 배포 점검 — 적용 및 배포 후 실행

```powershell
py -3 tools/verify-final-operations.py
```

최대 8개 HTTP 요청 중 실제 AI 요청은 고정 상담 1건이다. 서버 설정의 AI 사용량이 발생한다. 원본은 날짜 폴더별 JSON으로 보존하고 자동 통과를 쓰지 않는다. --dry-run은 입력 준비 확인만 한다. 이번 준비에서는 --dry-run만 실행했다.

| 항목 | 기대 결과 | 확인 한계 |
|---|---|---|
| health | 200, revision=로컬 HEAD | 불일치·실패 시 중단. 지속 가동률·처리 인스턴스 SHA의 독립 증명 아님 |
| page | 200, AI 안내 문자열·required 체크 입력 존재 | 실제 브라우저 렌더링·동의 클릭 검사가 아님 |
| script | 200, /api/chat 호출 문자열 | UI 전체 동작 검사 아님 |
| /.env 및 /static/.env | 403 또는 404 | 두 경로만 점검. 다른 파일·라우트 전체 보안 감사 아님. 응답 본문 저장 안 함 |
| consent=false | 403, 동의 안내 | 실제 AI 미호출은 서버 코드·회귀 검사와 함께 해석 |
| consent 미제공 | 403, 동의 안내 | 기본 동의 우회 방지 |
| consent=true 상담 | 200, 입력 경험에 맞는 확인 질문 2개, 공고 검색하지 않음 | 실제 답변 수동 검토 필요. 텍스트 모델·이 순간 처리만 확인, 이미지·Brave 키 상태 전체를 대표하지 않음 |

실패는 자동 재시도하지 않는다. 중단 시 나머지를 미실행으로 둔다. JSON의 상태·본문·요청 ID와 Render의 같은 시각 로그를 연결하되 키·인증 헤더·서버 환경변수 값은 공유하지 않는다. 오류가 나면 성공 결과만 남기지 말고 원인을 확인한 뒤 새 실행으로 보존한다.

## 계정 소유자가 직접 확인할 내용

- 평가 피드백에서 지적한 과거 노출 키가 공급자에서 폐기된 키와 일치하는지 확인. [기존 10월 29일 담당자 확인](../security-confirmation.md)은 그대로 보존한다. 지금 새로 독립 대조했다고 기록하지 않는다.
- 현재 Render에 새로 발급한 키가 등록돼 있는지, 공급자의 사용 권한·모델 접근·사용량이 가능한지 확인한다. 활성 키를 삭제하거나 키를 다시 만들라는 일괄 지시가 아니다.
- 코디세이 텍스트·이미지와 Brave의 역할을 구분한다. 각 성공 기록은 해당 요청 시점의 기능 동작 근거일 뿐 모든 키 설정의 독립 검사 아님.
- 결과 안내까지 Render 서비스와 API 이용 가능 상태를 유지한다. 휴면 복귀가 평가를 방해한다면 현재 운영 설정에서 해결할 방식을 검토한다. 주기적 호출만으로 가용성을 보장한다고 쓰지 않는다.
- 새로운 확인을 기록할 때 확인일·담당자·확인 범위만 적는다. 키 값·부분 값·인증 헤더·환경변수 전체 화면을 제출할 필요가 없다.
