# 상담 의도·도구 계획·목록 필터 보완

작성일: 2026-10-29. 기준 소스: a7722dd184982d91c907e665989b82b245370f66. 이 문서의 수정본은 로컬 자동 검사 완료 상태이며, GitHub 적용·Render 배포·실제 모델 재검증은 별도다.

## 관찰한 문제

1. `취업 준비를 도와줘` 요청에 상황 파악 질문 대신 공고 검색 결과가 표시됐다. 목록·모음·GitHub 저장소가 개별 공고 후보로 노출됐다. 응답 검색 시각은 2026-10-29 09:46:37 한국 시간이다.
2. `희망 직무가 아직 정해지지 않았습니다. 공고 검색은 하지 말고, 제 상황을 파악할 질문부터 해주세요.` 요청에 `AI가 올바른 도구 계획을 만들지 못했습니다` 오류가 표시됐다.

## 코드에서 확인한 원인과 변경

- 자동 모드는 정상 텍스트 응답도 도구 호출이 없으면 JSON 계획으로 전환했다. 일반 상담은 도구 없이 답변할 수 있게 하고, 학습 자료·공고·비교 등 도구가 필요한 요청의 기존 경로는 유지했다.
- JSON 계획은 최소 1개 호출을 강제했다. 일반 상담의 `calls: []`를 허용하고, JSON 형식이 깨진 일반 상담은 외부 도구 실행 없이 상담 답변 단계로 진행한다. 도구가 필요한 요청의 잘못된 계획이나 알 수 없는 도구를 실행 성공으로 처리하지 않는다.
- 검색 요청 여부를 모델 생성 검색어에만 맡기지 않고 현재 사용자 원문에서 검사한다. 검색을 요청하지 않은 일반 상담·명시적 검색 거부·입력 요건 비교에서는 외부 검색을 차단한다. 차단된 호출은 성공 tools에 넣지 않으며 공고 결과 렌더러로 상담 답변을 덮지 않는다.
- `/recruit`, `/junior`, `/theme/`, `/list/` 목록 경로와 일반 GitHub 저장소 및 채용 모음 제목을 추가 제외한다. 개별 Wanted·직행 공고 및 `/recruit/개별ID`는 회귀 검사에서 유지한다.

이 방식은 명시적인 요청을 우선하는 보수적인 검색 제한이다. `다른 것도 찾아줘`처럼 현재 문장에 공고 요청이 드러나지 않는 후속 요청은 검색을 차단할 수 있다. 공고 검색을 원하면 현재 질문에 `공고를 검색해 주세요`와 조건을 명시한다. 모든 자연어 표현이나 사이트 구조를 완벽히 판별한다고 주장하지 않는다.

## 검증

기존 74개와 신규 23개를 포함해 자동 검사 **97개 통과**. [JUnit 결과](counseling-fix-tests.xml).

- 네이티브 도구 없는 일반 상담의 직접 응답
- JSON 빈 계획과 비 JSON 일반 상담 계획의 처리
- 검색 요청 없는 상담·검색 거부·비교에서 외부 검색 함수 미호출
- 네이티브·JSON 양쪽에서 차단된 검색이 상담 답변을 덮지 않음
- 명시적 공고 검색·문서 검색 유지 및 필수 도구 요청의 빈 계획 거절
- 관찰된 목록·모음 5개 제외와 개별 공고 보존
- 기존 검색 필터·RAG·비교·입력 검증·서버 동의 차단 회귀 검사

AI 응답은 모의 클라이언트로, 검색은 모의 HTTP 결과로 검증했다. 실제 API 인증·LLM 응답·검색 결과·배포 성공을 뜻하지 않는다. 테스트 클라이언트 의존성의 사용 중단 예고 경고 1건이 있으며 실패는 없다. 기존 필터 검사의 검색 입력 1개는 명시적인 공고 검색 요청으로 갱신했다.
