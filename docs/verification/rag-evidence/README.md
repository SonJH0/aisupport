# RAG 인정 근거 및 재현 절차

작성: 2026-11-03. 소스 기준 4aece7d. 로컬 검색과 코드 전달 경로를 확인했으며, 후속 실제 배포 답변 3건도 [내용 검토](20261103T141726405327Z/README.md)했다. 공식 G3 인정 판정서는 아니다.

## 평가 기준과 실제 구현

첨부 평가 기준의 RAG는 질문마다 문서·DB를 검색하고 그 결과를 프롬프트에 넣는 방식이다. 이 서비스는 공식 문서 주제를 팀이 정리한 로컬 자료집을 사용한다. 웹의 원문 전체를 실시간 수집하거나 임베딩 검색을 하는 구현은 아니다.

| 단계 | 코드 | 확인 내용 |
|---|---|---|
| 본문 문서화 | ai/retrieval.py search_documents | knowledge.json sections의 실제 본문을 문단 ID·URL과 함께 구성. 가상 SAMPLE 공고는 검색 근거에서 제외 |
| 질문별 검색 | ai/retrieval.py rank_documents | 전체 문서 제목·본문의 단어 및 문자 bigram TF-IDF 코사인 순위. 기술·직무 3개를 if문으로 고르는 방식이 아님 |
| 초기 결과 전달 | ai/agent.py respond | evidence=search_documents(message), 시스템 메시지에 JSON 본문을 포함한 초기 검색 결과 전달 |
| 추가 도구 검색 | ai/agent.py run_tool 및 respond | LLM이 search_documents를 선택하면 실제 검색 documents를 tool 메시지로 다시 모델에 전달 |
| JSON 계획 경로 | ai/agent.py _json_agent | initial_evidence·tool_results·sources를 최종 생성 요청에 전달 |
| 표시 | ai/agent.py _finish | 본문 인용 ID에 대응하는 출처 표시. 인용이 없으면 sources가 비어 있을 수 있음 |

검색은 정해진 자료집을 대상으로 하지만, 모든 질문에 같은 문단을 고정 삽입하는 구조가 아니다. 소규모 자료집·어휘 기반 검색이므로 문서에 없는 내용, 동의어, 관련성 점수의 한계가 있다.

## 배포 응답 수집 — 다음 실행

새 스크립트는 고정 학습 질문 3개를 실제 서비스에 각각 1회 전송한다. 기능별 동일 입력 3회 안정성 시험과 구분한다. 외부 AI 사용량이 발생한다. 별도 키를 입력받거나 저장하지 않는다.

```powershell
py -3 tools/verify-rag-evidence.py
```

각 요청 직전 /health revision이 로컬 HEAD와 다르면 AI 호출을 생략한다. 일치한 경우 로컬 검색 본문·파일 해시와 실제 응답 answer/sources/trace·HTTP 상태·요청 ID를 저장한다. 실패를 자동 재시도하거나 통과로 표시하지 않는다. `--local-only`는 배포 요청 없이 로컬 검색만 저장한다.

### 배포 결과의 수동 검토 기준

1. HTTP 200 및 답변 존재 확인. 이것만으로 통과 처리하지 않는다.
2. health_before와 소스 버전 확인. 요청 직전 health는 응답 처리 인스턴스의 독립 증명이 아니다.
3. trace의 initial_retrieval 또는 search_documents 결과 ID와 질문의 관련성 확인.
4. 인용한 ID·출처와 실제 검색 문단의 주제가 맞는지 확인. 추가 도구가 다른 질의로 검색한 경우 로컬 초기 검색 목록과 같다고 가정하지 않는다.
5. 답변이 검색 문단의 내용과 추가 실습 제안을 구분하는지 확인. 자료 밖 설명에 출처를 붙이지 않는지 검토.

현재 응답 API는 검색 본문 자체를 반환하지 않는다. 로컬 검색 JSON은 배포 서버 내부 messages의 캡처가 아니다. 동일 버전 소스·로컬 자료 해시·전달 코드·회귀 검사·실제 서버 trace/answer를 함께 확인하는 증거 구성이다. G3 최종 인정은 평가자 판단이다.
