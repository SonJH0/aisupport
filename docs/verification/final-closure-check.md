## 실제 추가 시험: 성공·실패 구분

원격 Chrome에서 공개 서비스에 개인정보 없는 합성 질문을 입력했다. 각 시험은 페이지를 새로 열거나 새로고침해 시작했다.

| 회차 | 질문 | 미동의 상태 전송 | 동의 후 화면 결과 |
|---|---|---|---|
| 1 | HTML 폼·웹 접근성 학습 자료와 출처 요청 | 브라우저 ‘Please check this box if you want to proceed.’ 안내, consent=false·valueMissing=true·답변 영역 비어 있음 | ‘AI가 올바른 도구 계획을 만들지 못했습니다. 다시 시도해 주세요.’ 오류 |
| 2 | pandas 읽기·표 결합·요약 통계 학습 자료와 출처 요청 | 같은 브라우저 차단·미동의 상태 확인 | 같은 도구 계획 오류 |
| 3 | Python·FastAPI 신입 백엔드 채용공고 검색 요청 | 같은 브라우저 차단·미동의 상태 확인 | 12:50:04 KST 검색 결과. 개별 후보 7건 모두 추가 확인 필요, 제외 3건. 원문 링크·조건·모집 미확인과 search_live_jobs 표시 확인 |

세 화면 모두 ‘AI가 생성한 참고 정보입니다’ 고지와 코디세이 AI·Brave 전송 안내를 확인했다. 화면 차단 3/3은 확인했으나, 동의 후 정상 상담까지 포함한 통합 성공 3/3은 아니다. 새로운 학습 상담 2건의 실패를 기존 성공으로 바꾸지 않는다.

독립된 서버 요청은 12:46:18·12:46:23·12:46:28 KST에 consent=false로 POST /api/chat을 3회 전송했다. 모두 HTTP 403이며 본문은 ‘AI 처리를 위한 외부 전송 동의가 필요합니다.’였다. [1회](closure-20261029/consent-server-1.json)·[2회](closure-20261029/consent-server-2.json)·[3회](closure-20261029/consent-server-3.json) 원문 보존. 브라우저 요청과 같은 연결을 추적한 것은 아니므로 방법을 구분한다.

## 학습 계획 오류 보완

AI 도구 계획이 비JSON·calls 누락·빈 목록이면 순수 학습 질문에 한해 실제 로컬 search_documents를 수행하고 결과를 최종 AI 입력으로 전달한다. 이를 document_fallback trace로 구분한다. 공고 검색·입력 공고 비교·등록 공고 ID 요청은 이 경로로 대체하지 않으며, 알 수 없는 도구 이름도 계속 거절한다. 출력 답변을 성공 문구로 바꾸거나 학습 문서를 검색한 척하지 않는다.

변경 후 자동 검사 120개 통과(기존 113개+추가 7개). [JUnit](learning-plan-tests.xml). 이는 모델·실환경 성공을 뜻하지 않는다. 이번 로컬 코드는 사용자 저장소에 적용·배포되기 전이므로 실제 개선 여부는 미확인이다. 502의 원인 수정도 주장하지 않는다.

## 배포 뒤 남은 확인

최종 배포 후 FastAPI·MDN·pandas 상담 3건과 Python 검색을 확인하고, 동의 후 정상 응답까지 포함한 화면 절차를 다시 점검해야 한다. 실환경 결과를 받기 전까지 관련 Must 성공 횟수를 채우지 않는다. 기존 문서와 발표의 12:24~12:26 성공 기록은 당시의 선택 시험으로 보존하고, 이후 추가 실패와 배포 예정 보완은 이 문서를 함께 제시한다.

이번 추가 Python 검색은 앞선 Java·React와 함께 저장소 코드 4d0295b 이후 검색 3종의 핵심 기대 결과 근거다. 실행 중 배포 SHA를 독립 관찰하지는 않았다. 학습 상담은 추가 2건이 실패했으므로 같은 기준으로 성공 처리하지 않는다.
