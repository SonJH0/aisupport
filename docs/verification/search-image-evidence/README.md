# 3단계: 공고 검색·이미지 Must 배포 검증

작성: 2026-11-03. 준비 기준 소스: 7e31cbd. 이번 추가는 검증 도구와 절차이며 애플리케이션 코드는 변경하지 않았다. 입력 준비 검사를 통과했지만 실제 API 응답 검토는 아직 미실행이다.

## 실행

프로젝트 루트에서 실행한다. Python 표준 라이브러리만 사용하며 별도 API 키를 로컬에 넣을 필요가 없다. 배포 서버에 등록된 AI·검색 서비스 사용량이 발생한다.

```powershell
py -3 tools/verify-search-images.py
```

각 요청 직전 health revision이 로컬 HEAD와 같을 때만 실제 요청한다. 다르면 기록 후 중단하므로 Render 배포를 확인한다. 실패를 자동 재시도하지 않으며 요청별 원본·HTTP·요청 ID·시각·시간·배포 revision을 JSON으로 보존한다. health는 요청 직전 관찰이며 처리 인스턴스의 SHA를 독립적으로 증명하지 않는다. 개인정보 없는 고정 질문·기존 합성 이미지만 전송한다. 이미지 base64는 기록하지 않고 원본 경로·SHA-256만 저장한다.

특정 그룹만 필요하면 `--cases search` 또는 `--cases image`. `--dry-run`은 파일·입력 준비만 검사하고 네트워크 요청·결과 파일 생성을 하지 않는다.

이미지의 회사·직무·요건·금액은 실제 요청 질문에 복사하지 않는다. 위 기대 결과는 검토용 메타데이터에만 보존한다. 기존 선명한 영어 합성 PNG로 한정되며 한국어·흐린 이미지 정확성을 검증하는 시험이 아니다.

공고 3회·이미지 3회는 서로 다른 입력 각 1회다. 동일 입력 반복 안정성 검증이나 전체 G4 충족으로 확대하지 않는다. 각 기능의 기대 결과가 3회 중 2회 이상 나오는지 내용을 검토하되, 실패도 그대로 포함한다. 실제 모집 여부는 검색 요약으로 검증되지 않으며 별도 원문 확인이 필요하다. 후보 없음 안내가 맞는지 또한 도구 응답·검색 기록과 함께 검토한다.

이미지는 image_analyzed=true, image_analysis=ok와 이미지에만 있던 사실의 답변을 함께 본다. tools=[]여도 실패로 판단하지 않는다. UI 파일 선택·동의·표시까지 직접 조작한 시험과는 별도다. 근거 없는 요건·경력·급여 창작, 미기재 역량의 미보유 단정, 무관한 출처·조언 문제도 기록한다.
