## 손재형 본인 작성란

저는 AI 취업 코치 서비스의 AI·데이터 영역을 담당했습니다. 사용자의 질문에 따라 관련 자료를 검색하고, 채용공고를 찾거나 사용자 경험과 공고 요건을 비교할 수 있도록 AI Agent와 검색 기능을 구현·보완했습니다.

RAG에서는 학습 자료를 검색 가능한 문단으로 구성하고, 질문과 관련된 내용을 검색하여 AI 응답의 근거로 전달하도록 했습니다. 답변에는 참고 자료와 출처를 제공해 사용자가 근거를 확인하고 추가 학습으로 이어갈 수 있게 했습니다.

공고 검색 과정에서는 강의나 검색 목록 페이지가 개별 채용공고처럼 표시되는 문제를 확인했습니다. 이를 해결하기 위해 결과 필터를 보완하고, 검색 요약에서 확인되는 조건과 정보가 부족한 조건을 구분하도록 했습니다. 또한 사용자가 경험을 언급하지 않았다는 이유만으로 해당 역량이 없다고 단정하지 않도록 비교 기준을 보완했습니다.

배포된 서비스의 문서 검색·공고 검색·요건 비교·이미지 분석 결과를 확인하고, 입력과 응답 및 검증 범위를 문서로 정리했습니다. 실사용자 5명의 피드백도 익명으로 정리했습니다. 의견이 모두 긍정적이고 별도 수정 요청이 없어 기존 기능을 유지했으며, 피드백 이전의 기술적 수정과 이후의 검토 결과를 구분해 기록했습니다.

이번 작업을 통해 AI 기능은 응답 생성뿐 아니라 근거 제공, 정보 부족의 명시, 실제 실행 결과의 검증까지 함께 설계해야 한다는 점을 배웠습니다.

## 손재윤 — GitHub 기록 기반 기여 설명

> 아래 설명은 287e83e까지 공개된 저장소 기록 중 대표 커밋 f228f33의 코드 변경에 맞춰 검토자가 수정한 요약이다. 손재윤 본인이 새로 작성하거나 확인한 진술로 표시하지 않는다. [수정 전 본인 작성란](https://github.com/SonJH0/aisupport/blob/287e83e/docs/팀원별-기여.md)은 Git 이력에 보존한다.

손재윤 계정의 대표 커밋 [f228f33](https://github.com/SonJH0/aisupport/commit/f228f33)에는 FastAPI 기반 백엔드 진입점인 `backend/main.py`가 추가되어 있다. 루트 경로에서 프론트엔드 화면을 제공하고, `/static` 경로로 정적 파일을 제공하도록 구성했다.

요청 모델에는 사용자 메시지, 선택적 이미지, 최근 대화 이력을 정의했다. 메시지 길이, 대화 역할, 대화 이력 개수 등의 입력 제한을 두고, `/api/chat`에서 이미지가 있으면 `analyze_image`, 없으면 `respond`를 호출해 AI 처리 결과를 반환하도록 연결했다. 이 커밋의 API 연결을 해당 AI 함수 내부 전체의 구현 기여로 확대하지 않는다.

입력·처리 중 `ValueError`는 HTTP 400으로, 그 밖의 예외는 안내 문구와 함께 HTTP 502로 반환하도록 구성했다. 또한 프로젝트 루트의 `.env`를 `load_dotenv`로 읽도록 했다. 이 기록에서 확인되는 설정 작업은 `.env` 로딩까지이며, API 키·모델 선택 로직의 구현이나 배포 계정 설정을 했다는 주장으로 확대하지 않는다. 요청 모델에는 `consent`가 없어 동의 처리 구현도 이 커밋의 기여에 포함하지 않는다.

이 커밋에 포함된 `frontend/` 파일 세 개는 황준식 대표 커밋의 대응 파일과 내용이 동일하므로 별도의 프론트엔드 신규 구현으로 중복 계산하지 않는다. 현재 서버에는 이후 커밋의 수정이 누적되어 있으며, 위 설명은 초기 백엔드 구성·연결 범위다. 실제 실행 검증 수행·개인 학습 소감은 이 코드 기록만으로 확정하지 않는다.

대표 증빙: [f228f33의 backend/main.py](https://github.com/SonJH0/aisupport/blob/f228f334d9ffb4475d7310395b0df25ffc2e32e4/backend/main.py), [커밋·중복 파일 대조](verification/contribution-review-20261103/README.md).

## 황준식 본인 작성란

저는 AI 취업 코치 서비스의 프론트엔드를 담당했습니다. 사용자가 상담 내용을 입력하고 AI 응답을 확인할 수 있는 화면을 구성하고, 백엔드 API와 연결하여 서비스 이용 흐름을 구현했습니다.

상담·공고 추천·요건 비교 기능을 사용자가 구분할 수 있도록 화면을 구성했습니다. 입력 영역과 답변 영역을 배치하고, 참고 자료 링크를 통해 답변의 근거를 확인할 수 있도록 했습니다.

프론트엔드와 백엔드를 연결하는 과정에서는 사용자 입력이 요청 형식에 맞게 전달되는지, 반환된 답변과 참고 자료가 화면에 표시되는지 확인했습니다. 화면 구현뿐 아니라 실제 요청과 응답이 연결되는 과정을 점검하며 기능을 완성했습니다.

실사용자 피드백에서는 로그인 없이 바로 접근할 수 있는 점과 기능 구분이 직관적이라는 의견을 확인했습니다. 이를 통해 처음 이용하는 사용자가 서비스의 기능을 이해하고 사용할 수 있도록 화면을 구성하는 것이 중요하다는 점을 배웠습니다.
