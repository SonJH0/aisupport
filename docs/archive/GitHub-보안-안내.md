# GitHub에 API 키를 올리지 않기

## 팀원이 각자 할 일

- 실제 키는 각자 자신의 컴퓨터의 .env에만 입력한다. 키를 채팅, 이슈, PR, 스크린샷 또는 소스 코드에 넣지 않는다.
- .env.example은 사용자가 채울 변수 이름과 안내 문구만 포함한다. 여기에 실제 키를 적지 않는다.
- 커밋 전 VS Code 소스 제어 탭에서 변경 파일 목록을 확인한다. .env 또는 키가 들어 있는 파일이 보이면 커밋하지 않는다.
- 터미널에서도 `git status --short`로 커밋할 파일을 확인하고, 프로젝트 루트에서 `git check-ignore -v .env`를 실행해 제외 규칙이 적용되는지 확인한다. Git 저장소가 초기화된 뒤에 실행한다.

## 이미 Git이 추적 중인 .env가 있다면

.gitignore 추가 전 .env가 한 번이라도 추적되었다면 무시 규칙만으로 추적이 중단되지 않는다. 파일을 컴퓨터에 남긴 채 추적만 해제하려면 다음을 실행하고, 변경 내용을 확인한 후 커밋한다.

```powershell
git rm --cached -- .env
git status --short
```

이 명령은 현재 커밋에 파일을 제거하지만 과거 커밋의 기록은 지우지 않는다. 다른 이름이나 경로의 환경 파일도 추적 여부를 각각 확인해야 한다.

## 키가 과거 커밋에 들어갔다면

파일을 삭제하거나 저장소를 비공개로 바꾸는 것만으로 안전해지지 않는다. 외부에 노출된 키는 즉시 OpenAI에서 폐기하고 새 키를 발급해 .env에 교체한다. 기존 커밋 기록에도 남아 있다면 팀과 협의해 Git 기록 정리를 진행하고, 이후 각 팀원이 변경된 기록을 동기화한다. 기록 정리는 다른 팀원의 작업에 영향을 줄 수 있으므로 사전에 함께 확인한다.

.gitignore는 비밀이 다른 파일이나 커밋 메시지에 들어가는 경우를 막지 못한다. 커밋 전 파일 내용을 확인하고 사용 가능한 비밀 탐지 도구도 추가로 사용한다.
