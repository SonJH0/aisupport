# RAG·Agent 보완 내역

이 문서는 코드 보완과 기술 검증을 기록한다. 실사용자 피드백이나 평가 통과 증빙으로 꾸미지 않는다.

## 기존 문제와 변경

1. 기존 Agent에는 인터넷 검색과 ID 조회만 등록되어 있었다. 요청마다 관련 문서를 검색해 프롬프트에 전달하는 RAG 흐름은 실제 Agent에 연결되지 않았다.
2. 초기 문서 검색을 실제 요청 경로에 연결했다. 공식 기술 문서의 팀 요약을 문단으로 나누고, 저장 공고 후보도 본문 기반 TF-IDF 검색 대상으로 삼는다. 고정 직무 키워드 표를 사용하지 않는다. 다만 어휘 기반 검색으로서 동의어·의미 검색 한계가 있으며 규모가 작은 자료집이다.
3. LLM이 실제 호출할 수 있는 문서 검색과 공고 요건 비교 도구를 추가했다. 비교는 모델이 새로 생성한 경험이 아니라 요청 원문을 사용한다.
4. 네이티브 tool_calls를 실행하고 tool_call_id와 함수 결과를 연결한다. 허용되지 않은 도구·잘못된 JSON·잘못된 인자를 실행하지 않는다. 모의 응답으로 여러 호출과 호출 한도를 확인했다.
5. 코디세이의 강제 도구 선택 옵션은 실제 요청에서 `Requested feature is not supported`를 반환하여 사용하지 않는다. 네이티브 자동 선택을 사용하며, 기능 미지원 또는 도구 미실행 때는 LLM의 JSON 계획을 검증하여 실제 함수를 실행한다. 이 차이는 trace에 기록한다. JSON 계획도 모델의 선택이며 서버가 임의로 도구 이름을 바꾸지 않는다.
6. 초기 검색·도구 실행 성공/실패의 trace와 출처를 API에 반환한다. 사용자가 보낸 개인정보·API 키를 trace에 넣지 않는다.
7. 기존 OpenAI·Claude·Brave 키 이름, 대화 이력, 이미지 직접 분석, 프론트엔드의 /api/chat 경로를 유지했다. 동의를 서버에서 다시 검사하고 프론트엔드가 consent를 전송하도록 맞췄다.

## 확인 방법

같은 서버 http://127.0.0.1:8000 에서 화면과 API를 사용한다.

| 기능 | 입력/절차 | 기대 결과 |
|---|---|---|
| RAG | 상담에 `백엔드 API 요청 본문과 입력 검증 학습 자료를 찾아주세요` 입력 | sources의 문단 ID·출처와 trace의 initial_retrieval 및 관련 문서 확인 |
| 공고 추천 | `백엔드 개발자 채용공고 후보를 검색해 주세요` | search_live_jobs 실행, 실제 결과와 검색 시각 또는 설정·실패 안내. 원문·마감 상태 미확인 표시 |
| 비교 | 적합도 비교 화면에 경험 `Python API 개발, Java는 못함`, 공고 `Python API, Java, Kotlin` 입력 | compare_requirements 실행, 원문 근거와 정보 부족 표시. Java 언급을 보유로 오해하지 않는지 검토 |
| 동의 | /docs에서 consent=false로 /api/chat 호출 | 403이며 모델 호출 없음 |
| 입력 검증 | 공백 질문 | 422 |
| 이미지 | 기존 Anthropic 키를 설정하고 개인정보를 가린 선명한 공고 이미지 첨부 | 이미지의 실제 내용에 따른 답변. 이 수정본에서 실제 이미지 API 재검증은 별도 필요 |

각 Must 기능마다 실제 환경에서 세 번 시험하고 2회 이상 기대 결과가 나오는지 기록해야 한다. 자동 테스트와 API 기술 검사는 팀원 제외 5명 실사용자 테스트를 대신하지 않는다.

## 자동 검사와 실제 API 검사 구분

- `tests/test_retrieval.py`: 원래 있던 공고 조회/마감일 검사 보존.
- `tests/test_agent_api.py`: 본문 검색, 새로운 본문 인덱싱, 두 방식의 모델 선택과 실제 함수 실행, 인자 검증, 회수 제한, 동의·API 계약 등 검사. 모델/웹 응답은 모의 입력을 사용한다.
- `actual-api-check.json`: 실제 코디세이 API로 가상 질문을 전송한 기술 검사. 실제 응답과 시각을 기록하며 real_user_feedback=false이다. 이 파일의 passed는 도구 실행 및 응답 유무를 확인하는 자동 기준일 뿐 답변 전체의 정확성·채용 상태·합격 여부를 보장하지 않는다.

## 남은 한계

- 현재 검색은 TF-IDF 어휘 검색이고 문서집은 작다. 의미 검색이나 수집 자동화가 아니다.
- 공고 데이터는 일부 원문 미확인 후보이며 자동 동기화되지 않는다. 가상 공고는 실공고로 추천하면 안 된다.
- 비교 도구는 어휘상 근거를 모으므로 경력 기간, 부정 표현과 숙련도는 모델 및 사람이 확인해야 한다.
- 검색 결과가 있다고 실제 모집 중임을 뜻하지 않는다.
- 실제 이미지 OCR 품질, Windows 시작 스크립트 실행, 외부 배포 환경은 이 컨테이너의 단위 검사로 보장하지 않는다.
